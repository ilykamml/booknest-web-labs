# Компоненты и состояние BookNest

План составлен до переноса интерфейса на React. Основа — утверждённый main
083c90497527450413eace84f351d3f19fafd849. Дизайн и все 40 книг на полках сохраняются.

```text
App
├── Header → Button, Badge
├── FiltersPanel → Button
├── Catalog → Spinner, ErrorBox, EmptyState, BookList, Pagination
│   └── BookList → ShelfGroup → BookCard → BookCover, Button
└── BookDialog → BookCover, Spinner, ErrorBox, Button, Badge
    └── MotionStage
```

App владеет фильтрами, текущим разделом, страницей и выбранной книгой.
useLibrary хранит список желаемого и корзину, сохраняет их вместе с фильтрами
в localStorage. Счётчики, выборки и количество страниц вычисляются при рендере.
useResource владеет состоянием запроса и отменяет его при изменении параметров.
useDebouncedValue задерживает поиск Open Library на 350 мс.
ShelfGroup владеет только раскрытием раздела. BookDialog — фазой анимации и
запросом подробностей. DOM доступен через refs; документ из компонентов не ищется.

Презентационные компоненты: Header, FiltersPanel, Catalog, BookList, BookCard,
Button, Badge, Spinner, EmptyState, ErrorBox, Pagination. BookCover хранит
только пропорции загруженной удалённой обложки.
Button, Badge, Spinner, EmptyState и ErrorBox используются в разных частях интерфейса.

## Поток данных

Действие пользователя → иммутабельное обновление App/useLibrary → вычисление
выборки → JSX. Анимации вынесены в lib/motion.ts и получают DOM-узлы через refs.
Исходная карточка не пересоздаётся при заказе; лента появляется за сценой корзины.

## Каталог и сеть

«На полках» показывает утверждённый каталог: 40 доступных книг, ещё пять
находятся через поиск. «Open Library» выполняет реальный сетевой поиск от трёх
символов, с пагинацией по 20 записей и отдельным запросом подробностей.
Все fetch находятся в api/. Предусмотрены loading, success, empty и error,
отмена устаревших запросов и повтор после ошибки. Самостоятельная ЛР 4 не создаётся.

# Проверка ЛР 5

Запуск: Node.js 22.19+, `npm ci`, `npm run dev`. Для готовой сборки:
`npm run build`, затем `npm run preview`. Открывать через HTTP-сервер.

Команды проверки: `npm run build`, `npm run lint`, `npm test`.
TypeScript: `strict` и `noUncheckedIndexedAccess`. В приложении 16 компонентов,
из них 12 без собственного состояния. Максимальный размер файла компонента —
138 строк после форматирования. Button, Badge, Spinner, EmptyState и ErrorBox
применяются минимум в двух контекстах.

## Автоматические проверки

Девять тестов проверяют состав каталога (40 доступных книг, пять разделов по
восемь), поиск недоступных книг, совместное применение фильтров, сортировку без
мутации исходного массива, сохранение недоступных книг в желаемом, миграцию
старых числовых идентификаторов, параметры API и страницы по 20 записей,
нормализацию ответа, отдельный запрос описания, отсутствие запросов короче
трёх символов, HTTP 404/429/503, сетевую ошибку и отмену через AbortController.

## Браузер

- Все 40 книг и обложки, пять раскрываемых разделов; четыре книги в строке
  на компьютере, две на телефоне. Нет горизонтального переполнения при 320 и 375 px.
- Поиск и фильтр направления одновременно; пустая выдача.
- Реальный поиск `tolkien` в Open Library, сортировка по названию, вторая
  страница с другими книгами, отдельное полное описание The Hobbit.
- Общий список для местной и удалённой книги, восстановление после обновления.
- Ожидание ответа карточки, принудительный HTTP 404 и успешная кнопка «Повторить».
- Отключение сети: сообщение «Нет подключения к сети», восстановление и повтор.
- Открытие и закрытие карточки, заказ с лентой, отсутствие оставшихся копий
  книги и конфетти. При проверке по кадрам размеры летящей обложки положительные;
  к концу сцены исходная карточка видима.
- Заказ с `prefers-reduced-motion`: без сцены, состояние корзины обновляется.
- Закрытие по Escape и возврат фокуса к книге.

Настройки сети и уменьшенного движения после проверки возвращены в обычный режим.
Дерево настоящего React DevTools сохранено в [react-devtools.jpg](react-devtools.jpg).
Временные инструменты для этого снимка в сборку приложения не входят.

## Почему ключом служит id

После сортировки Clean Code может переместиться из первой позиции в другую.
Если ключом был бы индекс, React связал бы прежний компонент обложки с другой
книгой. Его локальное состояние пропорций или ошибки картинки осталось бы от
старой книги. Такая же проблема возникает при удалении книги из желаемого:
индексы следующих элементов сдвигаются. Стабильный id сохраняет связь состояния
с конкретной книгой; ключ строки полки также определяется первой книгой строки,
а не её порядковым номером. Местные id имеют префикс `local:`, удалённые — ключ
произведения Open Library, поэтому они не пересекаются.

Внешний поиск зависит от доступности Open Library; при отказе сервиса
показывается ошибка с возможностью повторить запрос. Локальные полки используют
данные и обложки проекта.
